# 会话存储

App 的 `ConversationStore` 管理聊天历史，SwiftAgentKit 负责 Agent 执行。聊天历史包含公开消息、服务商提供的可读思考、工具展示状态和附件引用，不包含图片原始字节、凭据、不透明推理或可恢复执行的工具队列。

## 目录与职责

App 沙盒的 `Documents/` 保存概要状态与会话资源，不增加产品名前缀：

```text
Documents/
├── state.json
└── sessions/
    ├── format.json
    └── YYYY-MM-DD_<会话 UUID>/
        ├── history.jsonl
        ├── metadata.json
        ├── attachments/
        │   └── <附件 UUID>/
        │       ├── original
        │       └── metadata.json
        ├── run-checkpoint-v1.json
        └── run-recovery-v1.json
```

日期前缀使用会话创建时间的 UTC 日期，创建后不随排序、继续聊天或设备时区改变。更早的任务记录没有创建时间时，采用首条回执时间或记录时间。只剩附件或检查点、找不到聊天记录的旧会话仍保留独立目录，以源目录时间作为日期；不会因此创建虚假的聊天记录。

`history.jsonl` 是聊天历史的真实来源。`state.json` 汇总会话 ID、相对目录、标题、模式、创建与更新时间、阶段、服务商与模型、Siri 入口状态以及有长度限制的预览；不包含消息正文、完整草稿、附件清单和执行检查点。有效时一次读取即可展示会话列表，不逐个扫描会话目录；打开会话或修改数据前才加载完整历史。

`metadata.json` 是各会话的可重建摘要，记录会话元数据、预览以及对应历史文件的大小与修改时间。`state.json` 缺失或损坏时从各会话摘要重建；会话摘要缺失或过期时再读取 JSONL。概要重建不触发迁移提示。写入或删除历史前先使总表失效，成功后再发布新的总表；总表写入失败不会撤销已成功保存的历史。

附件原始字节与引用分离，同一会话的草稿、消息、截图和远程图片都使用该会话的 `attachments/`。未发送的临时草稿可以拥有附件目录，但不创建历史文件，也不出现在历史列表中。首条消息提交后继续使用同一个目录。

`run-checkpoint-v1.json` 保存当前或最近一次任务的执行状态，`run-recovery-v1.json` 保留启动恢复时收集的历史记录。主运行实例与其他会话运行实例使用相同路径规则。执行检查点负责送达状态与恢复语义；JSONL 不承担授权或动作重放职责。文件按需创建，没有运行过的会话不必有检查点。

`format.json` 标识已初始化的新格式。删除全部会话后仍保留，因此旧备份不会再次导入。删除会话会删除其整个目录，包括聊天、附件和检查点；清理未引用附件只处理附件目录。

## 增量保存

JSONL 每行是一个完整保存事务，包含版本、会话元数据、变化的消息和移除的消息 ID。元数据保留标题、模式、创建与排序时间、草稿、服务商与模型选择、Siri 命令状态和草稿附件引用；其中消息数组为空。消息按 ID 更新，首次出现的消息追加到末尾。字符串内的换行由 JSON 转义，行末换行是事务完成边界。

只有发生变化的会话会保存，未变化的消息不会重复追加。流式更新短时合并保存，工具状态和结束状态立即保存。Siri 已准备的任务必须成功持久化后才报告已保存。磁盘历史不再按消息数量裁剪；发送给模型的历史上下文仍有独立的数量限制。

追加写入会同步文件内容。日志累计超过当前快照大小的八倍或 1 MiB 的较大值时，原子替换为当前状态快照；单会话文件上限为 64 MiB。压缩只影响当前会话，保留完整的当前消息、状态与附件引用，不承诺永久保留流式输出的所有中间状态。达到容量限制后显示保存失败提醒，保留内存内容与待保存标记。

文件使用完整数据保护，历史和附件遵循 Documents 的系统备份规则。此布局本身不启用 iCloud 跨设备同步。存储由 App 进程中的单个 `ConversationStore` 管理，不支持多个进程或外部编辑器并发写入。

## 一次性迁移

启动仅在新 `sessions/format.json` 尚不存在且发现旧数据时提示迁移。旧数据来自 `Library/Application Support/PhoneAgent/`，包括 `conversations-v1.json`、更早的任务记录、`Attachments/`、`Sessions/` 和根目录执行检查点；全新安装直接初始化。新格式完成后，即使旧文件仍在或 `state.json` 丢失，也不再次提示。迁移前不启动新任务、不删除旧历史，Siri 无法将新任务报告为已保存。失败后保留重试入口。

同一次迁移完成以下处理：

- 把旧归档转换为各会话的 JSONL，并生成列表摘要。
- 将 `Attachments/<会话 UUID>/` 的原文件复制进对应的会话目录，逐文件核对摘要；消息和附件 ID 保持不变。
- 读取根目录和 `Sessions/<会话 UUID>/` 的执行检查点，按记录内部的 `conversationID` 分配。旧目录 ID 与记录 ID 冲突时停止迁移，不将记录归给错误的会话。
- 合并同一会话的恢复记录，保留所有已有运行与未知送达状态；旧 USB 检查点也纳入同一流程。

数据先写入 Documents 内的临时目录，完成读取校验与附件字节校验后发布 `sessions/`，再发布可重建的 `state.json`。新旧数据根目录不同，不需要改名旧 `Sessions/`。迁移中断时从原数据重试；会话目录已发布而总表未发布时只重建总表。未发布的中间布局不属于兼容格式，开发模拟器中的此类残留单独人工整理。

旧归档、旧附件、旧 `Sessions/` 和根目录检查点保留在原位置；成功后不再用于正常读写。旧任务归档 `tasks.json` 也只作为迁移输入，不再更新。备份不会跟随新存储中的删除操作更新，仍可能包含已删除的历史和附件。

旧附件已经缺失或内容与引用不符时，迁移保留引用与现有字节并显示提醒，不伪造附件。检查点损坏、目录不合法或复制失败则不发布新存储，保留源数据并允许重试。

启动恢复将未完成回复与思考标记为中断，未确认送达的执行动作保留为结果未知，并可根据检查点补充工具展示状态。迁移和恢复均不会继续旧任务或重放旧动作。

## 故障处理与验证

JSONL 最后一行缺少换行时，只恢复此前完整的事务并显示提醒；下次写入先去掉未完成尾部，再追加事务。完整行损坏、版本不支持或文件过大时，保留该会话原文件并隔离读取失败，其他可读会话继续保存。新目录格式无法识别时禁止写入，不回退旧归档覆盖新数据。

删除失败保留界面中的会话。附件清理前必须加载全部历史并检查是否完整读取、是否完成迁移、是否有未保存修改，避免因引用缺失误删原文件。

默认核心测试覆盖增量写入、摘要重建与延迟加载、长历史保留、跨会话检查点分配、附件字节保留、迁移中断重试、尾部恢复、损坏隔离、压缩、删除和不重放。UI 测试使用合成归档验证启动提示、迁移后消息显示和重启不再提示。
