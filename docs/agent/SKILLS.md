# Local skills

Local skills live at `Documents/skills/<folder>/SKILL.md`. Additional Markdown/TXT references stay inside that folder. The displayed version comes from the top-level `version` field in `SKILL.md` frontmatter; the list shows it as `v<version>`, and packages without that optional field remain loadable with no version label. Skill Creator includes `version: 1.0.0` in new packages and explains how to maintain it. `SkillStore` scans these directories to derive names, descriptions, revisions and document catalogs. The library view refreshes while open. Each run starts with enabled skill names and descriptions in its system prompt; internal IDs and content revisions are not sent. `load_skill` takes only `name` and rescans the library on every call, so new or edited skills can be loaded immediately within the same run. Enablement controls inclusion in the discovery metadata, not explicit loading by name. If names collide, built-in skills take precedence; among local copies, an enabled copy takes precedence over disabled copies.

Importing a folder copies the full folder, including scripts and assets, into its own directory. Importing `SKILL.md` by itself copies only that file. Reimporting an identical folder reuses the existing package; changed imports retain separate versions, including changes to files outside the document catalog. Directory names provide stable skill IDs independently of content revisions. Enablement defaults to on. Only disabled skill IDs are saved in the `disabledSkillIDs` UserDefaults entry; enabling a skill removes its ID, and an empty entry is removed. Existing `.disabled` markers are migrated to UserDefaults and deleted when the store initializes. The User skills list appends `(Not enabled)` after the optional version only for disabled skills. Enabled skills have no status label. The enablement toggle is on the user skill detail page. Deleting a skill through the library removes its local directory.

Existing `Library/Application Support/PhoneAgent/Skills/skills-v1.json` data is validated and migrated into these directories with IDs, references and enabled state preserved. The archive is removed only after successful migration. Corrupt archives and conflicting destination contents are preserved and reported instead of overwritten. The archive is not used as ongoing skill storage.

The built-in `skill-creator` guides conversation-based creation using the existing [file and command tools](COMMAND-TOOLS.md). The root `SKILL.md` must be a regular UTF-8 file with valid frontmatter. A malformed entrypoint is skipped with a library warning and can be corrected on disk. `load_skill` returns the complete current `SKILL.md`, its directory and entrypoint path, and a catalog of readable UTF-8 Markdown/TXT references. Read references with the `read` tool using paths resolved from the returned directory. There are no skill-specific document count or size caps. Other files and unreadable references are omitted from the catalog and do not block discovery. Importing or loading a skill does not run its scripts. Supporting files are available separately through the normal file and command tools within their existing permissions.
