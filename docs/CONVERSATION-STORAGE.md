# 会话存储

App 使用会话目录保存展示信息、附件和设备执行检查点；AgentKit 使用同一目录的完整 JSONL 保存事务历史及模型上下文。展示投影和模型上下文由已提交事实分别构建：通知和草稿不会自动成为模型输入，历史工具结果也不是重新执行工具的指令。

## 目录与职责

App 沙盒的 `Documents/` 保存紧凑会话列表和各会话资源：

```text
Documents/
├── state.json
└── sessions/
    ├── format.json
    └── YYYY-MM-DD_<会话 UUID>/
        ├── history.jsonl
        ├── attachments/
        │   ├── <sha256>
        │   └── <附件 UUID>/
        ├── run-checkpoint-v1.json
        └── run-recovery-v1.json
```

目录名前缀使用会话创建时间的 UTC 日期；继续聊天、排序和设备时区变化不会改变目录名。只有附件或检查点而没有聊天记录的资源仍保持独立目录，使用资源时间作为日期，不因此创建虚假的聊天记录。`format.json` 仅标识 App 总会话目录的初始化格式；每个会话由自己的 `history.jsonl` 识别，不增加 `agent/` 子层。

`history.jsonl` 是权威来源：首行保存 schema、sessionID 和必要的迁移来源标识，后续记录内联完整事务。文本、消息 metadata、完整草稿、附件引用、可读思考、工具事实、原生续接状态与压缩基底均保存在日志中，不另写会话级 `manifest.json`、`metadata.json`、`history.index` 或每事务 blob。删除旧独立 metadata 文件不删除日志中的 metadata 字段。只有二进制图片按内容摘要保存在 `attachments/<sha256>`；它们与 App 已有的 UUID 附件目录并存。任意外部图片路径不会作为长期模型输入引用持久化。App UUID 展示附件缺失可显示占位；AgentKit 摘要图片是已提交事务的必要引用，扫描会校验它们，缺失时可能形成历史缺口，即使图片已不在当前窗口，也不能保证续接不受影响。

工具截图的展示引用来自已提交事务中的图片摘要、大小、类型和尺寸，不依赖另存一份 UUID 原图。实时展示在持久化成功后关联引用；重新加载时，即使缺少 App 附件 metadata，也可从原工具事务重建，无须改写历史或再次迁移。读取优先使用 UUID 目录的 `original`，缺失时读取同会话的 `attachments/<sha256>`，缩略图由原图派生。

附件路径校验先规范化已存在的会话目录，再检查其下的附件目录和文件；不对尚未创建的 UUID 子目录做真实路径字符串比较，避免沙盒路径别名导致误判。读取仍校验会话归属、文件类型、字节数和摘要，并拒绝附件目录或文件中的符号链接。

`run-checkpoint-v1.json` 和 `run-recovery-v1.json` 继续由 App 管理设备执行状态、送达事实及恢复记录。历史和附件不授予新的设备操作权限，不替代当前帧、一次授权、实时执行契约或停止释放检查。

## 紧凑列表与完整历史

`state.json` 是可重建的会话列表投影，保存会话身份、相对目录、标题、模式、创建与排序信息、阶段、服务商／模型选择、入口状态、短预览及历史文件大小／修改信息。普通预览和待确认 Siri 草稿预览均有长度限制，不能替代完整正文；完整草稿、草稿附件、消息与恢复信息仍在历史的 App metadata 事务中。修改这些值前先按需加载完整记录，不把预览写回为真实草稿。

读取列表时轻量枚举实际日期目录，并逐条核对已有概要的目录、历史大小与修改信息；只读取缺失或变化的会话来重建对应行，不因某一行过期而重扫全部历史。目录已删除的缓存行退出列表。旧概要布局首次读取时从日志重建，不在权威存储尚未转换时继续复用。`state.json` 缺失或损坏时可全部重建；单条形状、路径或身份冲突只使相应条目失效。列表保存失败不会撤销权威日志的追加或删除，也不阻塞 Agent 执行。

展示项使用稳定身份，后续更新不会产生重复消息；模型上下文保留有序用户输入、支持回放的原生响应与关联工具结果。图片和其他发送材料只在用户授权范围内参与上下文，旧展示附件引用不自动扩大授权。压缩快照只替换有效模型窗口，不删除完整历史或重新展示替换项。

## 提交与读取

会话头之后，每个完整换行记录是一笔自包含事务，包含身份、顺序、context revision、内容校验和内联正文。新增二进制图片先写入并同步，再追加引用它的事务行并同步。会话写锁、预期 revision 和事务身份共同避免并发冲突与重复提交：相同身份、相同内容返回原有回执；内容或 revision 冲突时不追加事实。展示和 metadata 更新不推进模型 context revision。

读取从完整历史重建展示投影和有效上下文。存储按 64 KiB 输入块扫描，单条完整记录上限为 256 MiB，日志总量没有固定上限。单张存储图片上限为 64 MiB；兼容旧内部布局时，单个旧 blob 上限为 64 MiB、旧信封行上限为 8 MiB。这些边界不扩大模型协议和运行时自身的限制，也不是新日志的总量阈值。单记录仍需完整解码并校验必要图片引用；分块读取不意味着跳过旧事实的完整性检查。`loadContext` 提供运行所需的基底、增量和调用账本，不假装返回全部事务；需要完整历史或重建公开上下文时通过明确读取入口获得。加载不会联系模型、申请设备授权、恢复旧任务或派发历史工具。

末尾没有换行的部分不算已提交记录；持有写锁后才能截断残缺尾部并继续追加。中间完整行损坏、未知必需格式或必要附件缺失时，保留原始文件，停止依赖该范围的续接与追加；可验证的展示前缀可读取并标明缺口。暂时不可写与真正损坏分别处理，条件恢复后重新核实，不把一次失败固化为永久运行状态。

用户可从损坏会话的可验证前缀显式建立新会话，保留可读展示与可验证附件副本，并在上下文中标识历史缺口。原会话和文件保留；旧运行身份、待处理调用、设备授权、草稿与服务商选择不会因此转移，历史工具只作为文字事实，不重新执行。

数据文件使用完整数据保护；保护数据不可访问时相关保存和设备输入停止。此布局不提供跨设备同步。清理附件须检查完整历史、有效上下文、迁移来源和活动任务，不能只依赖当前展示页或列表概要。

## 来源识别与迁移

`migrateLegacySync` 是统一准备入口：当前 JSONL 和无历史的会话不做导入；需要兼容时识别实际来源。AgentKit 读取旧内部 manifest／信封／blob 布局，App 自有 converter 转换过渡 UI JSONL。不同输入不是连续发布版本，也不构成原始归档迁移的必经链路。

原始 App 归档来自 `Library/Application Support/PhoneAgent/conversations-v1.json`，附件和设备检查点位于同一数据根目录或其会话子目录；更早任务记录也可作为来源。经用户确认后，转换器在隔离目标树中直接生成最终日期目录和完整内联 JSONL，不先写另一套会话格式。它核对会话身份、消息顺序、附件摘要及执行检查点，保留可还原文本和完整工具事实。缺失附件保留缺失状态，旧附件默认只供展示；未完成回复、审批和不确定送达动作收敛为中断或未知，不自动续跑或重放。验证完成后才切换目标树，失败保留原始归档与资源并允许重试；原始来源不随新会话删除自动删除。

已有会话目录的兼容转换持有写锁，使用 `.inline-migration.json` 记录迁移身份和来源摘要，保留本次校验过的临时来源，并构建完整临时 JSONL。整个候选及必要图片验证、同步后，原子替换 `history.jsonl` 并同步目录，作为唯一提交点；不再依赖另外发布 manifest。提交成功后清理旧会话辅助文件、每事务 blob 和本次临时来源，不保留永久 `legacy-v1` 或旧 JSONL 副本。清理失败只重试清理，不使已提交会话不可用，也不重新导入；未发布的操作从已验证来源恢复，不回退覆盖有效新历史。App 执行检查点和日志 metadata 字段保持各自职责，不因辅助文件清理而丢失。

旧内部布局还有一项有界兼容规则：经过旧格式标记与校验确认，仅含派生压缩基底、没有其他必要事实的事务，其原 blob 缺失时转换为显式恢复缺口记录，保留原 sequence 和 revision。严格审计仍报告原内容缺失；运行恢复可用此前有效基底及之后完整原始事实重建窗口，并停用旧响应链，不能声称恢复了原 opaque 字节。其他必要内容缺失不适用此规则；新内联格式的任意完整行损坏也不能因此跳过。
