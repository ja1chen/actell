# AgentKit

[English](README.md)

AgentKit 提供本地 Agent 运行时与会话历史，依赖 ProviderCore 的模型和协议类型。宿主负责注入模型服务、工具、授权与会话目录。加载会话只恢复数据，不执行工具，也不联系模型。

`JSONLSessionStore` 在传入目录中直接保存唯一权威 `history.jsonl`。首行标识 schema 和 session，必要时携带迁移来源；后续行内联完整事务。文本、消息 metadata、草稿、附件引用、原生续接状态与压缩快照均在日志中。只有模型二进制图片单独存为 `attachments/<sha256>`，与宿主 UUID 附件目录并存。不另写会话 manifest、metadata 文件、history index 或事务 blob；清理冗余 metadata 文件不删除历史中的 metadata 字段。

UI 历史与模型有效上下文分别由已提交事实投影。上下文快照替换模型窗口，不删除此前历史；展示与 metadata 更新不推进上下文 revision。文件锁、CAS、事务身份与尾部恢复保护提交。宿主紧凑会话列表是可重建缓存，保存失败不撤销权威历史，也不阻塞执行。

`migrateLegacySync` 是准备入口：当前 JSONL 和无历史情形不做导入，旧内部 manifest／信封／blob 布局由存储直接识别，过渡 UI JSONL 由 App 自有转换器处理；原始 App 归档可直接生成最终格式。调用方核对旧身份和附件引用，设备执行检查点仍由宿主原有恢复流程负责。完整临时 JSONL 验证、同步后才原子发布，以替换 `history.jsonl` 为提交点。随后清理旧辅助文件、事务 blob 和本次临时来源；清理失败只重试清理，不阻塞已提交会话或重复导入，不永久保留旧历史副本。

扫描按 64 KiB 输入块进行，单条完整记录上限为 256 MiB，历史总量没有固定上限。存储层的单张二进制图片上限为 64 MiB；旧来源兼容另限制单个 blob 为 64 MiB、旧信封行 8 MiB，Provider 和 runtime 的限制独立生效。每条记录均需解码并校验必要摘要图片；图片即使已离开有效上下文，缺失仍可能形成历史缺口。宿主 UUID 展示附件另有缺失占位策略。缺少换行的尾部尚未提交，只能持有写锁后截断。完整记录损坏或必要数据缺失时停止续接与追加，已验证展示前缀仍可读取，并标明完整性缺口。上下文恢复读取已提交基底、增量和调用账本；完整历史及公开事实重建使用明确的读取入口，必要记录不能静默变成空默认值。旧内部布局中经确认的纯压缩内容缺失会转换为显式缺口记录，保留 sequence 与 revision；严格审计仍报告缺失，运行恢复可据完整原始事实重建。此兼容例外不允许跳过新内联格式的损坏完整行。已获授权的宿主在提交前将磁盘模型图片转成字节，不持久化任意外部图片路径。

宿主标记的设备观测使用可配置保留策略，默认在 8 MiB 图片目标内保留最近三组观测。最新完整观测组即使单独超过目标也会保留，传输字节上限仍然生效。未超过组数或字节预算时，请求前缀保持不变；超过预算后，AgentKit 在安全边界提交替换快照并清除 response chain head，保留用户附件、所有工具调用／结果关联、完整展示历史和原生压缩返回的规范前缀。旧观测图片只从模型有效上下文中移出。
