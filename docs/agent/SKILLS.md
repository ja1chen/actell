# Local skills

Local skills live at `Documents/skills/<folder>/SKILL.md`. Additional Markdown/TXT references stay inside that folder. The displayed version comes from the top-level `version` field in `SKILL.md` frontmatter; the list shows it as `v<version>`, and packages without that optional field remain loadable with no version label. Skill Creator includes `version: 1.0.0` in new packages and explains how to maintain it. `SkillStore` scans these directories to derive names, descriptions, revisions and document catalogs. The library view refreshes while open, and each new conversation run rescans before taking its immutable enabled-skill snapshot. Files created or edited during a run are available through skill discovery on subsequent runs; the current run can read its new files with the normal file tools.

Imported packages are copied into their own directories. Reimporting identical content reuses the existing package; changed imports retain separate versions. Directory names provide stable skill IDs independently of content revisions. Enablement defaults to on. Only disabled skill IDs are saved in the `disabledSkillIDs` UserDefaults entry; enabling a skill removes its ID, and an empty entry is removed. Existing `.disabled` markers are migrated to UserDefaults and deleted when the store initializes. The User skills list appends `(Not enabled)` after the optional version only for disabled skills. Enabled skills have no status label. The enablement toggle is on the user skill detail page. Deleting a skill through the library removes its local directory.

Existing `Library/Application Support/PhoneAgent/Skills/skills-v1.json` data is validated and migrated into these directories with IDs, references and enabled state preserved. The archive is removed only after successful migration. Corrupt archives and conflicting destination contents are preserved and reported instead of overwritten. The archive is not used as ongoing skill storage.

The built-in `skill-creator` guides conversation-based creation using the existing [file and command tools](COMMAND-TOOLS.md). No dedicated save tool is required. Local packages retain the existing UTF-8 Markdown/TXT format and size limits; malformed packages are skipped with a library warning and can be corrected on disk.
