# 后台中断与结果恢复

## 已验证的性能原因

系统 CPU 限制曾导致进程终止；匹配版本的符号化采样将热点定位到后台仍更新的 SwiftUI 会话和审批展示。后台有执行资格不代表可以忽略系统 CPU 配额。

页面通知与执行记录分开：后台继续更新数据、保存文件、执行审批与设备控制，不发布隐藏页面的文字更新；回前台一次通知展示累计内容。受控合成流对比中，后台平均 CPU 从约 40% 降到约 3%；该测量证明展示通知的开销，不代表真实模型或 NCM 长任务的稳定性。

## 回执与恢复

工具完成必须在下一模型请求前持久保存结果和参数，不依赖与流式文字共享的 UI 观察队列。观察回调按 call ID 去重，迟到的开始事件不能把完成工具改回执行中。

启动时按会话、run ID、工具 ID 和名称核对检查点：

- 已确认送达：保留真实回执，不据此承诺画面效果正确。
- 已发送但未确认：显示结果未知，禁止重放。
- 准备但未发送：标记取消。
- 读工具缺失结果：不伪造图片或应用列表。

恢复不授予授权、不继续旧任务、不跨会话继承结果，也不覆盖明确失败。已有历史消息保留；实时活动跳转只负责导航。

有效内容进展可以更新活动新鲜度，没有进展时不伪造心跳。进程被杀后依赖系统 stale 状态与下一次启动的遗留活动清理。原始会话和系统日志留在忽略目录；诊断分别核对持久化事实、展示状态和系统中断原因。
