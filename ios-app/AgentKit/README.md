# AgentKit

[简体中文](README.zh-CN.md)

AgentKit is the local agent runtime and session history package. It depends on ProviderCore for model and protocol types; the host provides model providers, tools, authorization and a session directory. Loading a session restores data only and does not execute tools or contact a model.

`JSONLSessionStore` writes one authoritative `history.jsonl` directly in that directory. Its first line identifies the schema and session, with migration provenance when needed; subsequent lines contain complete inline transactions. Text, message metadata, drafts, attachment references, native continuation data and compaction snapshots stay in the log. Only binary model images are stored separately as `attachments/<sha256>`, alongside any host-owned UUID attachment directories. There is no separate session manifest, metadata file, history index or transaction blob. Removing a redundant metadata file never removes metadata fields from the history.

UI history and effective model context are separate projections of committed facts. A context snapshot replaces the model window without removing earlier history. Presentation and metadata updates do not advance the context revision. File locking, compare-and-swap, transaction identity and tail recovery protect commits. The host's compact session list is a rebuildable cache: failure to save it does not undo authoritative history or block execution.

`migrateLegacySync` is the preparation entry point. Current JSONL and absent history require no import; legacy internal manifest/envelope/blob storage is recognized directly, while transitional UI JSONL uses an app-owned converter. Original app archives can generate the final format directly. The caller validates legacy identity and attachment references; device execution checkpoints remain under the host’s existing recovery contract. It validates and synchronizes a complete temporary JSONL before atomic publication; replacing `history.jsonl` is the commit point. Only then are old auxiliary files, transaction blobs and migration temporary sources cleaned up. Cleanup failure is retried without blocking the committed session or repeating the import; no permanent old-history copy is retained.

The scanner reads in 64 KiB input blocks, accepts complete records up to 256 MiB, and imposes no fixed total-history limit. Storage limits each binary image to 64 MiB; legacy import additionally bounds each old blob to 64 MiB and each old envelope line to 8 MiB. Provider and runtime limits remain independent. Each record is decoded and its required digest images are verified; a missing image may create a history gap even after it leaves the active context. Host-owned UUID display attachments have a separate missing-placeholder policy. A missing newline leaves an uncommitted tail, which is truncated only while holding the writer lock. Damaged complete records or missing mandatory data stop continuation and writes, while the verified display prefix remains readable with an integrity-gap indication. Context restoration reads the committed base, tail and call ledger; full history and public-fact reconstruction use explicit read operations. Required records cannot silently become empty defaults. A verified missing pure compaction payload from legacy internal storage becomes an explicit gap record preserving sequence and revision: strict audit reads still report the loss, while runtime recovery may rebuild from complete original facts. This exception never permits skipping a damaged complete record in the inline format. Authorized hosts materialize disk-backed model images before commit; arbitrary external image paths are not persisted.

Device observations stamped by the host use a configurable retention policy: by default, keep the latest three observation groups within an 8 MiB image target. The newest complete group remains available even when it alone exceeds that target; transport byte limits still apply. The prepared prefix remains unchanged until the group or byte budget is exceeded. At a safe boundary, AgentKit commits a replacement snapshot and resets the response-chain head while preserving user attachments, every tool call/result pair, full display history, and the canonical prefix returned by native compaction. This transformation removes old observation images only from the effective context.
