# 系统配对与身份

在主 App 的手机操控设置中发起配对，按提示进入系统开发者模式界面完成密码/PIN 确认。本地网络权限、Developer Mode 和匹配的开发者镜像是控制的必要条件。主 App 的 VPN 与 ESP32 路线复用同一身份。

配对由 App 发布 `_remotepairing-pairable-host._tcp`，系统主动连接 App。后续控制连接仍须经过所选传输并重新验证身份；配对成功不能代替控制链路验收。发现无候选时不猜端口、不隐式回退。

## 持久化约束

身份使用 App 文件保护并排除备份，包含控制者私钥及绑定对端的长期公钥等敏感字段。页面、日志和共享文档不得输出 PIN、原始身份或密钥。

Rust 在对端签名验证后分别提供 provisional / committed 身份；Swift 原子写入并同步后才确认持久化，协议未取得确认前不发送最终消息。未完成记录不等于成功配对；先验证已有身份，失败不自动删除、覆盖不同绑定、降级已提交状态或重新配对。

配对监听有独立期限和后台执行条件。系统拒绝后台资格时须明确报告，不能在没有监听的情况下引导用户完成系统流程。普通 Lockdown 导入只属于高级诊断，见 [LOCKDOWN.md](LOCKDOWN.md)。
