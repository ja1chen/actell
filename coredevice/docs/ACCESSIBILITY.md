# 只读无障碍观察

“手机操控”中的“屏幕信息模式”决定本地模型任务读取并发送给模型服务商的内容，默认使用“截图”。无障碍文本和结构可能包含屏幕外内容。完整工具结果和模型上下文保存在会话 JSONL 中，续聊时原样恢复，避免因加载历史时改写节点正文而破坏缓存前缀。聊天界面临时从原文提取状态和节点数量，不另存展示摘要，也不把展示摘要写回模型上下文；显式上下文压缩另行记录并复用新基底。Muse 远程截图保留截图契约，不受本地模式影响。

| 模式 | 工具行为 |
| --- | --- |
| 截图 | 只采集截图，返回图片、尺寸及截图引用，不读取 AX。 |
| 无障碍内容 | 读取 AX，并返回用于点击、拖动的显示逻辑坐标范围；不采集或发送截图。不可用时返回原因，不自动改为截图。 |
| 截图+无障碍内容 | 分别采集两者；AX 不可用时仍返回截图及 AX 失败原因。 |
| 自动 | LLM 根据任务与前次结果，为每次观察明确选择前三种方式之一；App 不根据规则代选，也不自动重试。 |

现有观察工具继续使用 `screenshot` 名称，界面显示“查看屏幕”。自动模式在工具参数中提供必填 `mode`，允许 `screenshot`、`accessibility`、`screenshot_and_accessibility`；固定模式不提供此参数。模式在任务开始时固定，设置界面在运行期间禁止修改。旧 `accessibilityTreeEnabled=false` 迁移为截图，`true` 迁移为截图+无障碍内容；新设置优先，不回写历史工具结果。

四种模式均保留点击、拖动、输入文本、启动应用等操作工具。含截图的观察使用截图整数像素；纯无障碍观察使用 AX 的逻辑点，支持小数。模型依据节点 frame 选择可见目标，用工具结果中的 `input_coordinates.bounds` 判断坐标范围；不能把逻辑点直接当成截图像素，也不能把屏幕外节点当作可点击位置。自动模式的坐标单位由最近一次观察决定，每次观察替换旧引用。纯无障碍工具结果在历史中不显示缺失截图提示。

纯无障碍观察从认证连接读取显示信息，核对主显示器与触控显示器身份、方向、物理边界和逻辑点比例，返回 `input_coordinates` 的状态、单位和边界。点击、拖动换算为归一化触控坐标，沿用一次性授权、会话隔离和派发前几何校验。读取显示几何可能准备现有触控所需的 DisplayService 视频流，但不会请求截图、编码图片或向模型发送图片。当前逻辑点输入支持主显示器原生竖屏；不支持的几何或输入准备失败只使输入坐标暂不可用，AX 正文仍返回，模型可继续其他操作或重新观察。失败不自动重试、不重放触控，也不把旧截图作为隐式回退。

读取复用现有配对、隧道和 RSD 服务目录，通过 `com.apple.accessibility.axAuditDaemon.remoteAXService` 的原始 DTX 连接执行只读 AXP 请求，不启动 XCTest Runner，也不发送 AX 按压或滚动操作。首版将产品读取限制在 iOS 27.0、系统构建 `24A437` 与 AX API 26 的组合；其他组合明确报告不可用。开发者模式、开发者服务和当前连接路线仍是前提；首次配对和开发者镜像准备不因此变为免电脑。

## 观察边界

- 读取先对主显示器中心点执行无触摸命中测试，取得该点所属进程的应用根和深快照，再检查根、命中进程及显示几何是否变化。中心命中不是前台 App 的可靠证明；键盘、弹窗或浮层可能属于其他进程。结果保留命中方式、点、PID 和 `scope=process-at-point`，不额外生成前台状态判断。
- 当前任务通过 `launch_app` 成功启动应用后，工具结果会返回 `bundle_id` 和 `pid`，已运行应用也使用同一启动回执契约。回执表示启动请求已返回进程信息，不证明应用已显示在前台。原生后端不向模型暴露可执行路径或 audit token。
- 仅首次中心命中返回整数错误码 `8` 且没有结果时，允许使用当前任务、当前控制连接内最近的启动 PID 追加一次读取。先在两秒内核对该进程仍存在且可执行路径与启动回执一致，再新建 AX 服务连接，通过请求类型 `1` 取得该 PID 的应用根，校验 PID 和应用根标记，读取快照并复核根身份。中心读取与回退共用三十秒总预算；其他错误、读取后的命中复核失败和显示几何变化不触发回退。未启动过目标时返回 AX 选择失败；组合模式保留截图，纯无障碍模式不自动切换。
- PID 回退结果使用 `selection.method=explicit-pid`、`reason=center_hit_unavailable` 和 `scope=requested-application`，表示指定应用的无障碍树，不能当作当前屏幕归属证明，也不表示应用已被判定处于后台。回到主屏、另一次启动、控制连接变化、任务结束、AX 失败或成功观察到另一进程都会清除旧目标；恢复历史不会恢复 PID。PID 与可执行路径校验可排除已退出和被其他程序复用的 PID，但不能证明同一程序在校验后没有重启，也不能证明页面始终不变。
- 快照只覆盖选定进程暴露的无障碍信息，不代表完整屏幕、所有窗口或完整 DOM。外部进程仅保留已识别的终端引用，不补造子树。
- 截图、树和输入几何分别采集，`atomic=false`；根和显示几何稳定不代表页面内容未变化。原生 frame 使用逻辑点；纯无障碍输入只在返回可用逻辑坐标边界时使用，含截图的输入仍以截图像素为准。保留现有授权流程，派发成功不表示目标界面已发生预期变化。
- 每次读取使用新的服务连接与应用根；节点 ID 仅在对应快照内有效，设备内部 token 不交给模型或写入会话记录。字段缺失、null、false、零和空字符串分别保留；超限或结构不符时不输出被截断的成功树。
- AX 失败时向模型返回来源和失败类别，不把失败表示成空页面；组合模式仍返回截图，纯无障碍模式不额外采集截图。停止订阅确认与本地写端关闭分别报告；没有确认不能记为成功停止，也不把本地关闭写成远端确认。已建立会话的读取异常不自动切换 VPN、重新配对或重放输入。

## 实现与验证

AX 读取失败的诊断写入 App 文档目录下的 `background-execution-events.log`，并输出到系统日志／Xcode 控制台。除原有 `stage`、`cause` 外，记录原生请求序号、当前阶段、AX 请求类型、总耗时、阶段耗时和订阅确认耗时；已取得目标时记录目标与复核 PID。`selection_initial` 表示首次中心命中，`selection_verify` 表示快照后的中心命中复核；显示信息查询、应用根读取和快照读取也有独立阶段。

回退期间的失败诊断另保留 `fallback_from=selection_initial` 和初次错误码，`target_validation` 表示进程核对阶段；后续阶段只记录当前错误，避免把首次命中错误误认为 PID 读取错误。是否回退由协议处理的类型化结果决定，不依赖诊断 JSON 是否成功生成或解析。

远端错误只提取数值错误码、长度受限的错误域标识、值类型和是否附带结果，不记录错误描述、`userInfo`、界面文字、节点 token 或完整协议响应。诊断作为不超过 2 KiB 的可选数据附在原失败事件中，缺失、损坏或日志写入失败均不改变错误分类、连接保留和截图降级行为，不增加等待、重试或设备操作。

`coredevice/rust/src/ax_dtx.rs` 对控制会话、语义回复和分片施加边界；`ax_observation.rs` 管理单次回退和总预算；`ax_archive.rs` 将 NSKeyedArchiver 对象表解析为普通数据而非实例化私有类；`ax_snapshot.rs` 校验层级并生成快照内路径。归档 UID 图与二进制 plist 容器分别设置深度上限。每个会话只允许一个在途语义请求，超时或响应不一致后关闭该 AX 服务连接，保留原有截图及输入连接。

真实设备已验证本机回环通道、协议协商、指定 PID 和中心命中读取，以及固定测试页面的文本、标识和可用矩形。竖屏固定页面的单个按钮叠加位置与截图相符；受限后台执行窗口内曾读取系统设置进程。通用几何映射、横屏、显示缩放、第三方 App、长期后台、首次授权历史与重启恢复仍需分别验证，不能由上述结果推断。
